# Fieldfolio 2.2.0 — контекстное обновление (полный патч v3)

## Как работает

- `ResourceCoordinator` — один на процесс. Он хранит последний Android GPS-fix и погодные показания, а также выполняющиеся запросы. Уход элемента из Lazy-списка НЕ отменяет начавшийся GPS/HTTP-запрос.
- UI сам регистрирует потребности через `rememberDeviceFix`, `rememberWeatherReading`, `RegisterDeviceWeatherRefresh` или `OsmFocusPointFeed`. При уничтожении/паузе композиции подписка освобождается.
- Отдельные `RefreshScope` для просмотрщика и Preview собирают ресурсы присутствующих UI-компонентов. Pull to Refresh обновляет их, сохраняя существующую перезагрузку отчёта. Сами карты **не получают** перехватывающего свайпы Pull to Refresh.
- Полноэкранные карты используют только общий polling. Встроенная карта может участвовать в pull родительского документа, но жесты самой карты остаются за OSMDroid.
- `AdaptiveOsmMap` принимает произвольное число `OsmFocusPointFeed` и отдельных tracked points. По умолчанию подключён feed устройства; `focusPointFeeds = emptyList()` отключает его. Идентичность точек — ID, совпадение координат не удаляет участников.
- При появлении координат устройство появляется в списке и как маркер. **My last known location** остаётся доступным при отсутствии GPS/разрешения с реальным временем Android-измерения. Старую точку не объявляем свежей при чтении кеша.
- Clock с `deviceLocation` означает **системный часовой пояс Android**, а не запрос GPS. Часовой пояс обновляется через событие системы и на `ON_RESUME`.

## Защита от лишних запросов

| Источник | Автоматическая политика | Ручное обновление |
|---|---|---|
| GPS | Единственный цикл при активных подписчиках, шаг 30 секунд; провайдер может использовать кеш | Получение нового fix мимо кеша; одинаковые одновременные запросы объединяются, пауза 2 сек после завершения |
| WeatherAt(point) | Появление виджета → пауза 350 мс → проверка; далее раз в минуту проверяется актуальность; сеть не чаще истечения 20-минутной свежести либо после 60-секундной задержки ошибки | Только конкретная точка; пока HTTP работает, повторный вызов присоединяется к нему, после завершения действует 10-секундная пауза |
| WeatherAt(DeviceLocation) | Один общий GPS и стабильная погодная точка (изменяется при перемещении ≥1 км) | Сначала свежий GPS-fix, **потом** погода по выбранной точке |
| DeviceTimeZone | События Android | GPS и HTTP не нужны |

- До 3 погодных запросов выполняются одновременно. Автоматические запросы, дождавшиеся очереди после исчезновения всех своих подписчиков, отбрасываются **перед HTTP**.
- Запущенный запрос принадлежит Coordinator, поэтому исчезновение виджета из Lazy-списка не оставляет его в вечном Loading и не запускает запрос заново при возвращении. Подписки освобождаются с 7-секундной задержкой (кеш живёт независимо).
- Кнопка обновления WeatherCard работает и в успешном состоянии. При загрузке она показывает индикатор и неактивна; после ручного запроса становится доступной по истечении 10 секунд. Pull в Weather Preview работает независимо от кнопки, но использует тот же запрос.
- При ошибке ранее полученная погода остаётся на экране с предупреждением; по истечении 20 минут показывается признак устаревания.
- Системное разрешение на геолокацию проверяется после callback и при возвращении на экран; если активным потребителям нужен GPS, координата запрашивается после успешного разрешения.

## Document API / VFS

- Обычный `Folio.vfs.get(...)` читает снимок из существующего `DocumentAccessContext`: никаких HTTP-запросов во время чтения VFS.
- **Активный** Notebook Runtime регистрирует потребность в GPS, если в его отчёте присутствует Location или Weather с `deviceLocation`: в том числе скрытый узел, на который может ссылаться JavaScript. Это сохраняет возможность получать обновлённые снимки в VFS без отдельного таймера на каждый WebView.
- Help не запрашивает GPS через VFS: его `DocumentAccessContext` не содержит погодного провайдера.
- Реактивные подписки непосредственно из пользовательского JavaScript (`Folio.watch(...)`) **не добавляются**: существующий контракт VFS остаётся read-only и без привилегий на прямое управление источниками.

## Проверки и ограничения

- 15 Kotlin-тестов `ResourceCoordinatorTest` (включая медленный HTTP 2,35 сек, многократные нажатия, прокрутку во время загрузки, очередь из невидимых Weather, последовательность GPS→Weather, получение разрешения).
- 8 Kotlin-тестов моделей списка точек/маркеров, включая совпадающие координаты разных участников и замену `current-location` без дубля.
- 15 Python-тестов, 6 подтестов и 38 WebView-ресурсов.
- Полная Android-сборка и проверка на устройстве не выполнены: Gradle Wrapper в среде без сети не может скачать Gradle 8.11.1, Android SDK отсутствует.
- Реальный источник участников в версии 2.2.0 отсутствует. Он добавляется через `OsmFocusPointFeed`. Старые не-Document экраны, которые сами используют `LocationWeatherController` или напрямую вызывают `WeatherProvider`, продолжают существовать; этот патч не переписывает все их UI-сценарии.

## Меню направлений карты (v4)

- Текущая/последняя геолокация устройства отображается одной точкой. На карте отчётов
  её маркер создаёт общий `DeviceFocusPointFeed`, а не отдельный маркер маршрута.
- `Focus target` — переход к точке, а не дополнительный объект. Если цель уже есть
  среди маркеров или отслеживаемых точек, второй пункт не добавляется. Для
  источников с асинхронными координатами можно передать `focusTargetMarkerId`.
- Несколько *разных* участников на одних координатах сохраняют отдельные пункты.
  `Current map center` остаётся отдельной командой даже при совпадении координат.
- Обновление устройства и запрос разрешения доступны компактной кнопкой-иконкой
  справа от заголовка окна. Кнопка показывает подсказку; во время GPS-запроса
  отображается индикатор и повторное нажатие блокируется. Новых жестов карты нет.

## Настройка списка направлений (следующий патч поверх v4 + Last Fix / Weather)

- В настройках появился раздел **Map** после Audio (в двухколоночном режиме — в правой колонке).
  Переключатель **Show current map center** сохраняется локально и действует на все карты.
  Изначально включён, чтобы поведение после обновления не изменилось без выбора пользователя.
- Отключение убирает только строку `Current map center` из `Focus destination`.
  Камера, маркеры, `Focus target`, GPS, погода и кнопка обновления локации не меняются.
- Порядок пунктов теперь определяется расстоянием до origin: сначала все совпадающие
  с origin точки, затем остальные — от ближайшей к дальней. Тип `Current` не имеет
  преимущества перед выбранной точкой. Совпадающие участники остаются отдельными строками.
